# PayOS Premium setup

Basic users can purchase one calendar month of Premium for **2,000 VND** at
`/app/mail-admin`. Paid Premium users can renew from the same page. Each renewal
extends the later of the current expiration or payment confirmation time by one
calendar month (UTC, clamped to the last day for shorter months). This is a
customer-initiated monthly payment, not an automatically charged subscription.
An administrator's existing Premium grants remain unlimited and separate.

## Connect the payment channel

1. Sign in to [my.payos.vn](https://my.payos.vn/), complete the account and bank
   verification required by PayOS, and create a payment channel for OmniMail.
2. Open the channel's integration credentials. Copy its **Client ID**, **API Key**
   and **Checksum Key** to the **API service** on Render → Environment:

   ```dotenv
   PAYOS_CLIENT_ID=the-channel-client-id
   PAYOS_API_KEY=the-channel-api-key
   PAYOS_CHECKSUM_KEY=the-channel-checksum-key
   ```

   For local API development, put these in `apps/api/.env`. Do not add them to
   `apps/web/.env`, any `VITE_*` variable, GitHub source, screenshots or chat.
   Client ID alone is insufficient; all three values belong to the same channel.
3. Confirm `WEB_APP_URL=https://omnimail.io.vn`, production Firebase Admin access
   and persistent Firestore storage are configured, then redeploy the API.
4. Register this channel's webhook URL in PayOS:

   ```text
   https://omnimail-api.onrender.com/api/billing/payos/webhook
   ```

   This endpoint accepts signed PayOS registration samples, requires no Firebase
   login, and rejects invalid signatures. Unknown sample order codes are
   acknowledged without changing any account.
5. Sign in as a Basic user and open **Upgrade**. The payment button becomes
   available once the API has all three credentials and persistent storage.
   Without configuration it stays disabled and the Admin request option remains.
6. When ready, make one deliberate 2,000 VND payment from a test customer account.
   Verify the account becomes Premium, the expiration is shown, refreshing the
   page preserves it, and resending the same webhook does not add a second month.
   Do not make an additional payment while the first is being verified.

The return/cancel URLs are generated by the API under
`https://omnimail.io.vn/app/mail-admin`. They do not need a separate frontend
route. Returning with `status=PAID` alone never activates Premium.

## Verification and storage

- The server owns the price (2,000 VND), user ID, order code and return URLs.
- The official `@payos/node` SDK signs requests and validates provider response
  signatures. Webhooks are verified before any order lookup or account change.
- Activation additionally fetches the signed PayOS payment record and checks
  order code, link ID, amount, amount paid, remaining amount and paid status.
- `premiumOrders` stores orders; `premiumBilling` stores pending checkout state
  and subscription expirations. Firestore transactions commit payment completion
  and expiration together. Repeated or concurrent delivery cannot double-credit.
- Pending checkout links are reused for 15 minutes. Failed/uncertain requests
  retain the order code so retrying can recover a link already created at PayOS.
- Expirations are restored before the API starts. HTTP authorization checks the
  expiration on every request; no permanent Premium claim is issued for payments.
- Status checks reconcile missed/slow webhooks. A return URL, forged webhook,
  underpayment or another user's order cannot grant Premium.
- Admin role changes revoke the paid entitlement before applying the manual
  role. Disabling/deleting an account blocks payment activation.
- A delayed payment for an order created before an Admin revocation requires
  manual review; it cannot silently undo the Admin's decision. Contact the
  customer and handle the payment/refund before changing access manually.
- This implementation does not issue refunds or automatically debit a bank
  account. Handle refunds in the merchant's normal PayOS/banking process.
